# ТонПлат — комплект для публикации

Все файлы сайта находятся **в корне архива**. Загрузите содержимое архива (не сам zip) в корень публичного репозитория GitHub; GitHub Pages: `Settings → Pages → Deploy from a branch → main → /(root)`. Файл `index.html` должен лежать в корне репозитория. `.nojekyll` не даёт Jekyll пытаться обрабатывать статические файлы.

## Что входит

- `index.html`, `styles.css`, `tokens.css`, `legal.css` — сайт и стили.
- `config.js`, `menu-data.js`, `app.js`, `privacy.js` — локальные данные меню, корзина, формы, настройки хранения.
- `privacy.html`, `consent.html`, `cookies.html`, `terms.html` — юридические страницы.
- `404.html`, `robots.txt`, `.nojekyll` — служебные страницы и настройки.
- Фотографии и логотип — локальные, без CDN. В исходном архиве не было объявленных шрифтов, поэтому используются безопасные системные альтернативы без внешних загрузок.

## Что изменено

- Номера/артикулы не выводятся ни на карточках блюд, ни в списках блюд (внутренние ID сохранены для работы корзины).
- Подвал сокращён: только краткие сведения об организации, контакт и ссылки на документы.
- В формах есть отдельное **неотмеченное** согласие; введённые данные не отправляются автоматически на сервер. После заполнения посетитель сам выбирает мессенджер, отправляет сообщение и при необходимости вручную вставляет текст в Telegram.
- Никаких сторонних трекеров и куки; Web Storage по выбору (корзина в рамках вкладки либо долговременное сохранение); настройки можно изменить.
- Включена базовая CSP через HTML meta, запрещены сторонние скрипты и сетевые запросы из JS.

## Важно перед запуском коммерческого сайта

1. **Проверьте юридические данные** (юр. адрес, ИНН/ОГРН, телефон, email), цены, наличие блюд, заявления о халяль, гарантии сроков и доставке. Всё взято из предоставленного сайта, без проверки в реестрах.
2. **Согласуйте правовые документы с юристом** и приведите их в соответствие с реальными процессами работы с заявками, перепиской, сроками хранения, договорами с исполнителями и фактическими каналами передачи данных. Наличие страниц само по себе **не означает** соблюдение всех требований 152-ФЗ.
3. Уточните, требуется ли оператору **уведомление Роскомнадзора** об обработке ПД; определите ответственное лицо, внутренние процедуры, сроки и место хранения данных. Учтите требования локализации данных при сборе ПД граждан РФ. Сайт не содержит сервера для хранения заявок.
4. **HTTPS**: GitHub Pages предоставляет его при корректной настройке. Если подключите свой домен, настройте HTTPS. Серверные заголовки безопасности (HSTS, X-Content-Type-Options, Referrer-Policy, frame-ancestors) задаются на уровне хостинга/CDN, а не статическими файлами GitHub Pages.
5. **Не публикуйте ключи, токены или webhook-ссылки с секретами в JavaScript**. Для автоматического приёма заявок понадобится отдельный сервер с ограничением доступа, защитой от спама, обработкой согласия и безопасным хранением.
6. Нет подключённой аналитики и рекламы. Перед их установкой обновите согласие и политику cookies; до согласия не загружайте сторонние трекеры.
7. При использовании мессенджеров оцените соответствие их использованию правилам для передачи персональных данных и требованиям законодательства РФ; добавьте альтернативу для клиента, который не хочет ими пользоваться.

## Быстрая проверка

Откройте сайт по HTTPS. Проверьте все фотографии, фильтры, наборы, добавление в корзину, отправку WhatsApp/Telegram (для Telegram требуется вставка текста), формы согласия, документы и обе кнопки настройки хранения. Тестируйте на телефоне и компьютере.
